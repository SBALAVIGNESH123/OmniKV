# OmniKV benchmark smoke report — 2026-07-14

This checked-in report is a reproducibility artifact, not a marketing
performance claim. It documents the benchmark workflow and expected structured
output shape for issue #20.

Run profile:

- profile: `smoke`
- OS/arch: Windows x86_64
- Rust: `rustc 1.96.1 (31fca3adb 2026-06-26)`
- Git commit reported by the harness: `fa19620f5a8e1d5597daca95a34bc623d8c2874d`
- Source state: local issue #20 working tree on top of that commit
- command:

```bash
cargo bench -p omnikv-engine --bench reproducible_bench -- --profile smoke --json-out target/omnikv-benchmark-smoke.json
```

Workloads covered:

- single-node write-heavy point writes
- single-node read-heavy random hits
- single-node mixed 80% read / 20% write
- single-node range scan
- single-node compaction from memtable to L0 and L0 to L1
- single-node transaction commits
- replicated-simulated Raft log append, follower fan-out, apply, and mark-applied

Metrics captured in the JSON report:

- throughput in operations per second
- p50 / p95 / p99 latency in microseconds
- process RSS at workload start and end when the OS exposes it
- process user/system CPU deltas when the OS exposes them
- data-directory bytes at start and end
- disk growth bytes
- WAL size at workload end
- compaction elapsed time and SSTable counts for the compaction workload

On this Windows run, process RSS and CPU deltas were emitted as `null` because
the lightweight benchmark harness currently samples those fields through Linux
`/proc`. CI Ubuntu runs populate those process-level fields.

The replicated workload is explicitly named `replicated-simulated` because it
uses three local `OmniRaftStorage` instances without network transport or
process isolation. Full distributed, networked benchmark results should be
published separately after issue #16 hardens partition and failover behavior.
